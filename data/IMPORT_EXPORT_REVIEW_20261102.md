# Import–Export — Paket tambahan 32

Menu Import–Export kini menyediakan cadangan JSON untuk Kotoba dan Kanji buatan pengguna. Ekspor dapat memilih Kotoba/Kanji/keduanya serta semua level/N5/N4. Materi bawaan, audio, riwayat, favorit, progres buku dan pengaturan tidak termasuk cadangan ini. File dibuat memakai Blob UTF-8 dan nama berakhiran .json. Contoh format tersedia untuk diunduh.

Impor membaca berkas .json maksimal 5 MiB dan 5.000 baris. Envelope wajib format dex-gaku-custom-data, version 1 dan data.kotoba/data.kanji berupa array. Tidak mengubah data saat memilih atau mempratinjau file. Pratinjau menampilkan jenis, nomor baris, kata, bacaan, arti dalam file, level, status dan alasan. Ada filter status dan pemuatan 20 baris bertahap. Pengguna menekan Impor N data baru sebelum menyimpan; Batal tidak menulis. Baris tidak valid dan duplikat dilewati, dengan jumlah keduanya ditampilkan pada hasil.

Validasi mengikuti form: Kotoba wajib jp/rom/meaning/level, kana opsional; Kanji satu karakter Han, level N5/N4, on/kun boleh kosong, guratan 1–64, radikal opsional dan paling banyak dua contoh yang harus memuat karakter itu. Data terlalu panjang ditolak, tidak dipotong diam-diam. Duplikat Kotoba memakai penulisan/alias pada level yang sama, termasuk normalisasi Unicode/spasi; Kanji dibandingkan lintas level. Duplikat di antara baris file juga dilewati. Impor tidak mengganti arti data yang sudah tersimpan. Level mengikuti file, bukan preferensi aktif. Metadata JSON tambahan dipertahankan; ID impor dibuat ulang supaya tidak bertabrakan dengan ID lokal. ID legacy custom-N dipertahankan saat penulisan pertama. Form edit Kanji kini mempertahankan contoh kedua dari impor ketika contoh pertama diedit/dikosongkan.

Data dibaca ulang saat konfirmasi. Bila snapshot perangkat berbeda, pratinjau diperbarui dan pengguna diminta meninjau sebelum menekan Impor lagi. Pemilihan file baru mengabaikan hasil pembacaan async file sebelumnya. Semua teks file di-escape. Versi format tidak didukung, berkas rusak, data lokal rusak dan batas ukuran/baris memberi pesan.

Penyimpanan kedua daftar memakai jurnal gaku-data-import-journal-v1. Penulisan prepared menyimpan snapshot sebelum/sesudah; perubahan menjadi committed adalah satu pergantian visibilitas logis. Semua pembaca data buatan pengguna (termasuk inisialisasi Kotoba saat reload) membaca sisi before ketika prepared dan sisi after ketika committed. Baru kemudian dua kunci lama disalin dan jurnal dibersihkan. Jika copy terhenti, kedua daftar tetap terlihat konsisten melalui jurnal. Pemulihan bisa dicoba dari UI; CRUD biasa menolak menulis jika penyelesaian jurnal gagal. Kegagalan sebelum committed mempertahankan data lama. Jurnal rusak tidak ditimpa. Ini tidak menyediakan transaksi terdistribusi antar-tab: pembacaan snapshot dan penolakan pratinjau usang mengurangi risiko, tetapi perubahan simultan persis pada sela operasi localStorage tetap mungkin berlomba. Impor memerlukan ruang tambahan untuk jurnal dan dapat ditolak jika kuota tidak cukup.

55 berkas tes lulus, termasuk roundtrip/filter ekspor, Blob/download link dan pembersihan URL, preview tanpa tulisan, duplikat, validasi/escaping, metadata/ID, cancel, batas file/baris, balapan pembacaan file, pratinjau usang, kegagalan commit, recovery committed yang setengah tersalin, reload dan perlindungan data rusak. Browser pada fixture memori 390px diperiksa: ekspor, pratinjau 2 baru/1 duplikat/1 invalid, Batal dan hasil impor (dua daftar bertambah satu). Event unduh asli berhasil ditangkap pada halaman langsung; pada iframe event unduh tidak tersedia. Isi unduh divalidasi lewat tes Blob, bukan pembacaan ulang berkas browser yang dibatasi. Belum Android fisik.

Paket 32 adalah tambahan untuk Paket 30. Uji audio Bab 1 yang sedang dikerjakan ditunda sesuai permintaan pengguna dan tidak disertakan. Installer memeriksa baseline Paket 30, konflik hash, cadangan, seluruh tes serta rollback. Tidak commit/push/deploy otomatis dan tidak mengubah localStorage pengguna saat pemasangan.
